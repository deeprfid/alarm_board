# RS485“雷达/摄像头有人”实时上传 —— 链路设计（设计稿 v0.1）

> 状态：**设计稿，未改动任何固件代码**（仓库基线 v0.1.0 保持）。
> 范围：STM32F0 中继板 v4.31 ↔ HC32F460 报警板 V4.2 之间的 5 条 RS485 点对点链路 + STM32→Linux 上报段。

## 1. 背景与目标

- 客户新需求：每块 HC32 报警板把**雷达/摄像头“有人”状态实时上传**；
- Linux 主机收到“有人”即启动 RFID 读标签 → **端到端实时响应是关键**；
- 传感器口径（已确认）：雷达输出 IO 电平 0/1，**100ms 刷新一次（10Hz）硬指标**；摄像头输入**已去抖**；客户只关心**有人/无人布尔**。

## 2. 已确认决策

| # | 决策 | 内容 |
| --- | --- | --- |
| D1 | 拓扑 | STM32 共 6 个 UART：USART1=Linux(IPC@115200)；USART2..6=5 条 RS485，**每条点对点固定挂 1 块 HC32，无需寻址** |
| D2 | 硬件 | RS485 收发器**硬件自动换向**；两端需偏置电阻使空闲=mark 高 |
| D3 | 内容 | 仅“有人/无人”布尔；**无人不传（静默）** |
| D4 | 状态码 | HC32→STM32：**有人=0x55，无人=0xAA**（互补码，单字节即消息，无帧头无 CRC） |
| D5 | 上报语义 | 无人→有人：上沿(EXINT)立即**双发** 0x55；有人期每 **20ms** 心跳 0x55；有人→无人：发**一次** 0xAA 后静默 |
| D6 | 归属补全 | HC32 字节不含身份；**STM32 在 RX 中断内按接收口补“串口号+通道号”**再转 Linux |
| D7 | Linux 帧 | STM32→Linux：**[0x7E][串口号][通道号][0x55/0xAA]** 共 4 字节（IPC@115200，可升 460800） |
| D8 | 仲裁 | RS485 半双工**非对称先听后说(LBT)**：主站(STM32)抢占优先，从站(HC32)只在主站让出的静默窗开口 |
| D9 | 转发 | STM32 收到状态字节后 **RX 中断内原地归属补全 + 非阻塞入队** COM1（不攒帧、不经过主循环） |

## 3. 延迟预算（人进入 → Linux 收到“有人”）

| 段 | 最坏时延 | 归属 |
| --- | --- | --- |
| 雷达检出 + OUT 刷新 | ≤ **100ms**（硬指标） | 传感器，外部不可控 |
| HC32 EXINT 上沿→发射 | ≤1ms | 固件可控 |
| 关键帧静默守卫 G_edge | 0.5~1ms | 固件可控 |
| 0x55 上线 1B | ≈22µs @460800 | 物理 |
| STM32 ISR→COM1 入队 | µs 级 | 固件可控 |
| IPC 4B | ≈0.35ms @115200（升 460800≈0.09ms） | 固件+Linux |
| **固件可控合计** | **≈2ms（不含雷达量化）** | — |

**结论：雷达 100ms 量化占端到端约 98%，主导“实时”指标，本固件无法消除。** 若客户要 <100ms 启动 RFID，只能改走 LD2410 串口原始数据（见 §9），本次 IO 方案不含。

## 4. 性能余量

- HC32F460 **主频 200MHz**：10ms 状态机 + 3 路 EXINT + 周期单字节发送的 CPU 占用可忽略（远 <1%），**冗余很多**；将来补 LD2410 串口解析/快速判定也仍有余量；
- STM32F0（hub）主频 40MHz（客户口径），**职责仅数据中继分发**：新增工作只是“收侧识别状态字节 → 查表补串口号/通道号 → 非阻塞转发”，不承担重处理；5 口全有人 ≈ 每口 1B/20ms，逐字节中断负载远 <1%，无需 DMA、无需升波特率。

## 5. 协议

### 5.1 HC32 → STM32（RS485 段）

| 线上字节 | 含义 |
| --- | --- |
| 0x55 | 有人（上沿首帧×2，之后 20ms 心跳） |
| 0xAA | 无人（仅有人→无人瞬间一次，随后静默） |
| （静默） | 无人稳定期不发任何字节 |

- 0x55/0xAA 逐位互补（汉明距离 8）：单比特干扰不可能互相误判；
- 无 CRC：噪声字节可能被当成状态，但互补码保证不会“假有人/假无人”互换，且 20ms 重发 + 无人静默使误报窗口 ≤1 心跳；
- 可选增强（默认不做）：STM32 要求“线静默≥阈值后的字节”才采信；或连续 2 个相同字节才采信。

### 5.2 STM32 → Linux（IPC 段 4B）

| byte0 | byte1 | byte2 | byte3 |
| --- | --- | --- | --- |
| 0x7E 同步 | 串口号 1..5 | 通道号 | 0x55 有人 / 0xAA 无人 |

- 同步字 0x7E 与状态码/串口号值域不相交 → Linux 无歧义分帧；
- 丢字节自愈：20ms 心跳 + 同步字搜索，1~2 帧恢复；重复 0x55 幂等；
- 通道号 = 业务部署号，STM32 内静态映射表给出（默认口↔通道 1:1，可配）。

## 6. HC32（从站）状态机

- 输入：雷达 OUT PC14/PC13/PH2（任一高=有人）；摄像头 IN1 PB00（已去抖，低有效取反）；IN2 PB01 仅本地报警用，不上传；
- 上沿：EXINT 边沿中断（PC14/PB00 中断框架现成：bsp_exint.c Ext_Init / AICAM_INT_Init，补 PC13/PH2）；输入 100ms 量化远大于中断响应，边沿不漏；
- 上沿发送：不做软件去抖（雷达量化本身即稳定周期），走关键帧快速窗双发 0x55；
- 有人期：10ms 节拍状态机，电平保持有人则每 20ms 发 0x55（非边沿计数）；
- 下沿：2~3 拍确认后发一次 0xAA，随后静默（下沿允许晚几十 ms，无副作用）；
- 发送：启用 USART4 TX（当前未使能）。单字节量极小：阻塞写 1B≈22µs 无害，或复用现成 TX-DMA（Uart4_DMA_Trans）由 DMA-TC 门控，实施二选一。

## 7. RS485 仲裁（媒体访问控制）

### 7.1 不变量
- I1 互斥：任意时刻总线最多一个发射者；
- I2 优先级：竞争时主站必胜，下行报警不被上行心跳阻塞。

### 7.2 规则（非对称静默门限 LBT）

| 规则 | 对象 | 内容 |
| --- | --- | --- |
| R1 | STM32(主) | 下行前须静默 ≥ G_m=0.3ms；不计自己 TX 回环 |
| R2 | HC32(从) | 常规上行(心跳/0xAA)前须静默 ≥ G_s=3.0ms；期间见字节即作废重计 |
| R3 | HC32(从) | 关键帧(有人上沿)快速窗：静默 ≥ G_edge=0.5~1ms 即发，连发 2 遍(间隔~0.5ms) |
| R4 | STM32(主) | 一次下行突发 ≤ N_burst=1~2 帧(≈0.7~1.4ms) |
| R5 | STM32(主) | 下行突发后强制让线静默 ≥ G_s 再发下一段（让出上行窗） |
| R6 | HC32(从) | 发完一帧后本 20ms 心跳周期内不再发（天然最小帧间隔） |
| R7 | 双方 | 空闲电平保持 mark(高)，字节间不留碎发 |

### 7.3 为什么不会撞
- 从站起意时若主站正发/刚发完 <3ms → 静默计数不够 G_s，开不了口；
- 主站起意时若从站正发(1B≈22µs) → 主站等 0.3ms 即开；
- 两端同时起意：从站需 3ms、主站 0.3ms → 从站 ~0.3ms 听到主站字节自动退避，下个 20ms 心跳补发（自愈）；
- 从站唯一开口时机 = 线静默 ≥3ms，而 R5 保证下行后主站必让线 ≥G_s → 从站开口总在主站让出的窗口内；
- 关键帧快速窗安全性靠**事件因果**：雷达/摄像头先有人→才可能有下行 → STM32 此刻几乎不在发下行；µs 级竞态由双发冗余兜底。

### 7.4 边界场景
| 场景 | 行为 |
| --- | --- |
| 无人在场 | 线全静默，无冲突 |
| 上电即有人 | 去抖后线本静默→立即双发 0x55 |
| 主站连续报警 | 按 N_burst 分批、批间让行 ≥G_s；心跳最多延后几 ms |
| 人停在区内 | OUT 恒 1 无新边沿→靠 20ms 心跳维持上报 |
| 字节被干扰/撞掉 | 等下一心跳（≤20ms 自愈） |
| 时钟漂移 | 无绝对时隙，机制无关 |

### 7.5 硬件配合
1. 两端偏置电阻拉空闲为 mark 高，否则收发器释放后浮空→收端乱收干扰 LBT；
2. 自动换向即可，主站无需控制 RE/DE；
3. 主站“静默”以 RX 活动为准（USART IDLE/字节计时）。

## 8. STM32（主站）中断转发与互斥
- **识别**：通道口 RX ISR 识别 0x55/0xAA；排除下行回环干扰：要求**不处于自己 TX 期间且字节前线静默 ≥ G_rx_accept(默认 0.3ms，>9 字节时间)**——下行帧字节间距仅 22µs，回环字节不满足静默条件被滤除；
- **归属**：查口→通道映射表，组 [0x7E][串口号][通道号][state]；
- **非阻塞入队（禁止 ISR 内等 TX）**：ISR 不得调用主循环 comSendBuf()/UartSend()（TX FIFO 满会 while 死等）。新增 ISR 安全上行队列（单写者）：ISR 只入队，满则丢弃并置 pending；
- **单写者收敛**：USART1 TX 只有一个写入者——主循环或 USART1 TXE 中断把上行队列灌入 COM1，消除 usTxWrite/usTxCount 竞态；
- **负载**：5 口全有人 ≈250B/s（4B Linux 帧 ≈1KB/s），115200 占用 <1%，无需 DMA。

## 9. Linux 主机行为建议（Linux 工程，本仓库不含）
- 0x55→立即启动 RFID；0xAA→停止；
- 超时兜底：>3×20ms 无字节→按无人处理；
- 迟滞建议：0xAA 后 X ms 内再来 0x55 允许直接重启，避免 RFID 反复启停；
- 重复 0x55 为电平保持语义，无需去重。

## 11. 实施清单（后续立项，本次不改码）

**HC32（Radar V4.2）**
- 启用 USART4 TX（USART_TX 功能；阻塞发送或复用 Uart4_DMA_Trans）；
- 补 PC13/PH2 雷达 OUT 的 EXINT（PC14/PB00 现成）；
- 10ms 节拍新增有人状态机：上沿双发/20ms 心跳/下沿 0xAA/无人静默；
- 实现静默计数(G_s/G_edge)与发送门控；TX 期间不计自身回环；
- 复核与本地声光报警共存：上传只读 IO，不改报警判定。

**STM32（v4.31）**
- 通道口 RX ISR 增加“空闲窗+非自己 TX”的 0x55/0xAA 识别；
- 新增 ISR 安全上行队列（单写者）与 COM1 灌入；
- 串口号→通道号静态映射表；组 4B 帧发 Linux；
- 与主循环既有 COM1 发送串行化，避免竞态。

**Linux（外部工程）**
- 解析 [0x7E][串口][通道][state]：0x55→启动 RFID，0xAA/超时→停止（含迟滞）。

## 12. 对现有报警链路的影响
- 下行报警 PDU 优先级高于上行：LBT 保证主站可随时插队；
- 上行心跳负载 <1% 带宽，不影响下行实时性；
- 不改动既有 0xFF alarm_pdu 通路与声光报警判定；改动面收敛在“HC32 上行只读采样+发送”与“STM32 收侧识别+上报”；
- 设计定稿后再动代码，遵循 CHANGELOG + 单仓库 git 流程。
