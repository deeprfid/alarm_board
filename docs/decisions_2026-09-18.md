# 设计定稿备忘（2026-09-18）

> 本次收敛 OTA 的分发拓扑、协议与槽模型，作为实现依据。
> 设计细节以 `docs/ota_boot_design.md` v0.2 为准，本备忘是决策记录。

## 1. 分发拓扑：HC32F4A0 直连

- 由 **HC32F4A0 主机**经 RS485 直接对 HC32F460 报警板分发固件并升级；
- 放弃 v0.1 的「Linux → STM32 中继 → HC32」两跳路径（环节多、实现麻烦）；
- 依据：F4A0 物理上就在 RS485 一端；有文件系统 + QSPI + USB-MSC，可作固件仓库与版本管理节点；**离线可升级，不依赖 PC/Linux**；
- 本次范围外：STM32F0 中继板与 Linux 主机的 OTA 路径（暂缓）。

## 2. 升级期：关闭全部业务帧，链路独占

- 升级期间 HC32F4A0 与 HC32F460 **双方都停止全部业务帧**（0xFF 报警/参数、0x55 状态、0xAA 查询与应答），该链路只跑 OTA1 固件帧；
- 理由：半双工 RS485 上 34KB 下载会饿死业务帧；独占后两端状态机大幅简化；
- 超时兜底：任一方 10s 无进展即退出升级模式、恢复业务，避免链路被永久占死。

## 3. 协议：OTA1 帧（不新造）

- 采用既有 OTA1 帧，**不采用** v0.1 §9 建议的自建 0xA5/0xAA OTA 命令族；
- 依据：C# 上位机、Python 工具、F4A0 与扫描板固件三端已实现且经真机调优；
- 偏移语义取**串口语义（含 82B 包头的绝对偏移）**，与 USB 的「载荷相对偏移」严格区分；
- 分块 256B（正好落在雷达板 512B DMA 窗口内），34KB 整包约 1~1.5 秒。

## 4. 槽模型：A/B 双槽、无搬运（维持 v0.1）

- 维持 A/B 双槽即运行区、选择器标志选槽、版本号不参与选槽；
- **无搬运**：不做「暂存区 → 覆盖运行区」，激活只是翻一个标志；
- 代价与接受理由：需按槽编译**两份镜像**（A/B 各一份）；换来无脆弱搬运窗口、Boot 极简、磨损最小；
- **App 启动早期写 `SCB->VTOR = 本槽基址`**（M4 有 VTOR；STM32 M0 需向量表重映射，本次不涉及）；
- 布局：Boot 32K@0x0 / 槽A 128K@0x8000 / 槽B 128K@0x28000 / 标志双份 8K@0x7E000。

## 5. 借鉴来源

- **报警板（HC32F460）**：借鉴 `Scanner_20260901/boot_iap` 的 flash 擦写、OTA 状态与跳转决策、时钟/FCG 恢复、`RW_RAMCODE` RAM 驻留段的链接脚本写法，以及 `hc32f46_app/.../ota_transport_uart.c` 的设备端 OTA1 帧处理；
  **注意模型差异**：`boot_iap` 是 single_bak（QSPI 暂存 + 备份 + 搬运），与本设计的 A/B 无搬运不同，**只借鉴机制代码，不照搬其 QSPI 依赖、备份区与搬运流程**（报警板无 QSPI 外设）；
- **主机（HC32F4A0）**：借鉴 C# 上位机串口 OTA（`ReaderUI_v1_MCU/OtaUpdater.cs` / `OtaProtocol.cs`）的发送主循环与帧常量，以及 `tools/ota_send.py`。

## 6. 实现顺序

1. F4A0 侧 host 发送器（纯逻辑，只依赖「写字节 / 读字节」两个回调）—— 可离线自测；
2. 报警板侧接收端（OTA1 帧解析 + 写非活动槽）；
3. 报警板侧 A/B Boot（读标志 / 校验 / 跳槽 + TRIAL 回退）。
