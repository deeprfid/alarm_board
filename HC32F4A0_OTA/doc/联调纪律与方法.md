# 联调纪律与方法（教训固化）

> 2026-08-17 F4A0 启动/H2 联调复盘后建立。**每次真机联调前必须重读本节。**

## 一、核心纪律（时刻清醒）

1. **静态分析先行，再动真机**
   - 改代码前先用 grep/glob 精确定位：命令通道、调用链、socket 分配、数据流
   - 0 token 硬件成本的分析做足，真机只做"验证假设"
2. **一次只改一个变量**
   - 每次烧录只改一处，失败能归因
   - 禁止把多个未验证修复打包烧测
3. **最小验证链路**
   - 建立"最小可验证路径"再测完整流程：
     ping → connect → 单字节下载 → 完整 OTA
   - 每步独立确认通过，才进下一步
4. **日志过滤，不抓噪音**
   - 监听只抓关键词行（ota/error/connect/关键标记）
   - 禁止把 FlashDB 初始化、配置转储等无关日志整段打入上下文
5. **环境先确认**
   - COM 口占用、残留进程、服务器状态先清理验证
   - 避免 COM3 被占/串口消失反复踩坑
6. **先写测试计划再动手**
   - 明确：验证什么、预期什么、失败如何二分

## 二、避免的高成本循环

- ❌ 改代码 → 编译 → 烧录 → 抓全部日志 → 发现新问题 → 再改（10+ 次循环）
- ❌ 全盘 os.walk 列出几百个文件路径
- ❌ 转义/脚本错误反复编译失败才发现
- ❌ 变量不隔离，多个改动混在一次烧录里

## 三、H2 联调遗留（下次从这继续）

- 已定位：设备 connect 到 PC 的 TCP 不成功（服务器收不到设备连接，但 PC→设备可达）
- 线索：HTTP 监听占 SOCKET0/1；QSPI 暂存区下载前未擦除；命令走 json_remote_cmd（HTTP 响应下发）
- 下一步按"最小链路"逐级验证：先设备 ping PC → connect 任意端口 → 再 OTA

## 四、Token 使用纪律

- 工具调用输出：只取关键尾部/摘要，不整段读
- 定位用 glob/grep，不用 os.walk 全盘遍历
- 脚本转义问题：先本地验证再编译
- 每次工具输出先判断是否必要，再决定是否进上下文
